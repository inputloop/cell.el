#+TITLE: Tending cell-mode

* What this repository is

This is David O'Toole's /cell-mode/, an object-oriented spreadsheet
control for GNU Emacs, with its complete history from
https://gitlab.com/dto/cell-mode (41 commits, the last one =b600fc8=,
2021-12-26, version 2.3).  Everything up to that commit is David's,
unchanged.  What we have added since is listed below, one change per
commit, so each can be read, reverted or taken back upstream on its
own.

David has said to mint a stand-alone recipe from here; what, if
anything, he wants to do with it himself is his to decide.  Until he
says otherwise we keep this copy available and working, for ourselves
and for anyone else who uses it, and we offer every change back to him.

The repository is named =cell.el=, the name the project is known by.
The library inside is =cell-mode.el= and provides the =cell-mode=
feature.  David's older line, https://gitlab.com/dto/cell.el (2019,
MIT licence, provides =cell=), is a separate thing and is not part of
this repository.

* History and thanks

David first wrote cell-mode in 2006 and presented it at EmacsConf 2019
as "Object oriented spreadsheets with example applications"
(https://emacsconf.org/2019/talks/18/).  The application he showed
it with was his own: Mosaic, a music sequencer
(https://gitlab.com/dto/mosaic).  The idea underneath it is to drive a
user interface inside Emacs from a grid of EIEIO objects.  Each cell is
an object that can hold any Lisp value and answer events in its own
way, and an application subclasses cells and sheets to get the
behaviour it needs.

dungeon-mode (https://savannah.nongnu.org/projects/dungeon) took that
design as the model for editing a dungeon's tables in Emacs.  Its
editor, =dm-cell=, draws its own grid and shares no code with this
repository, but the approach of encapsulated cells driving the
interface is David's.  As far as we know, dungeon is the first project
downstream of his to build on it.  If you know of an earlier one,
please tell us.

David chose EIEIO at a time when Emacs Lisp programmers often heard
that the class system was more trouble than it was worth, and he made
it work.  That example encouraged dungeon to keep using EIEIO, which
also shaped its card-game experiments, now on their own as
card-games.el in MELPA.  Thank you, David.

* What changed since 2.3

| commit                                                        | what                                                |
|---------------------------------------------------------------+-----------------------------------------------------|
| Add a stand-alone recipe                                      | Makefile, first ERT suite, these notes              |
| tests: drive the commands as a user would                     | tests for every interactive command; found bug 4    |
| Fix sheet settings never being found                          | bug 1                                               |
| Fix comment cells being collected as data                     | bug 2                                               |
| Fix expression cells erroring on values that are not strings  | bug 3                                               |
| Fix cut losing the cell when nothing is selected              | bug 4                                               |
| Compile without warnings on Emacs 29                          | no change in behaviour                              |
| Package headers for the inputloop copy: version 2.4           | Version, URL, Maintainer, SPDX licence identifier   |
| CI: compile, test and prove-red                               | GitHub Actions, Emacs 25.3 to 30.1 and the snapshot |

The four bugs:

1. *Sheet settings were never found.*  =cell-sheet-collect-settings=
   bound =cl-values= but looped over the unrelated global =values=.
2. *Comment cells were collected as data.*  Their
   =cell-collect-value-p= method had only a docstring, so it returned
   that string, which is non-nil.
3. *Expression cells signalled an error for values that are not
   strings* (=cell-sexp->cell= on =7=, for example).  Such values are
   now labelled with their printed form.
4. *Cutting with nothing selected lost the cell*: it was blanked
   without being copied to the clipboard first.

Each was first pinned in the tests as an expected failure, then fixed
in its own commit, which turned the pin back into an ordinary test.

* Build and test

| command          | what it does                                                 |
|------------------+--------------------------------------------------------------|
| =make=           | byte-compile, then run the tests                             |
| =make test=      | run the ERT suite in =t/= against the source                 |
| =make prove-red= | show the suite can fail: a planted failure must turn it red  |
| =make compile=   | byte-compile =cell-mode.el= (warnings shown, not fatal)      |
| =make clean=     | remove compiled files                                        |

Use =make EMACS=/path/to/emacs test= to test a particular Emacs.  Last
local run: GNU Emacs 29.3, byte-compile silent, 35 tests, 34 passed, 1
skipped (the prove-red test, which runs only under =make prove-red=).
CI runs the same three targets on Emacs 25.3, 26.3, 27.2, 28.2, 29.4
and 30.1; its results are on the repository's Actions tab.

The suite covers the grid data structure, cells, a live sheet in a
buffer (rendering, collecting, saving and reading back through
EIEIO-PERSISTENT, undo), and every interactive command driven the way a
user drives it, with minibuffer answers supplied by the test.  A batch
or tty Emacs has no font to measure glyphs with, so when there is no
graphic display the tests measure label width in columns instead.  That
is the only stand-in the suite uses.

* Still open

- David's =todo.org= items (an =eieio-persistent= naming change, and
  paste/undo through =cell-sheet-read=) do not reproduce on Emacs 29.3.
  Both paths are covered by tests; the items stay open until someone
  can say what they were.
- The cursor-blink timer starts when the file is loaded and runs every
  half second from then on, even if no sheet is ever opened.  It does
  nothing outside Cell-mode buffers.
- The file still uses dynamic binding (=lexical-binding: nil=), and
  rendering depends on it: =cell-insert= and its siblings read =row=
  and =col= from their caller.  Moving to lexical binding is a larger
  change than any here and wants its own tests first.
- The README's own list of issues (cursor display with images, column
  alignment after font changes, no dependency resolution between cells)
  is David's and still stands.
